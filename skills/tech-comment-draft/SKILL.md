# 技术评论草稿（tech-comment-draft）

## 适用场景

用户想在他人的技术社区文章（掘金 / 思否 / 知乎等）下留言，需要一条**真诚、具体、
有观点**的评论草稿——目的是建立真实互动，而不是发垃圾评论。本技能只产出草稿，
**人工提交**（社区对自动刷评论有封号风险，绝不用浏览器自动化提交）。

## 步骤

1. **读对方文章**：
   - 用户给了链接 → 用 `browser-open` 打开并提取正文；或用户已贴正文摘要 → 直接用。
   - 若链接打不开 / 内容为空：请用户粘贴文章正文或标题，不要猜。

2. **提炼 2-3 个可对话切面**：从文章中找出值得回应、有争议或可延伸的点，例如：
   - 作者的核心结论或取舍（"为什么选 A 不选 B"）；
   - 某个工程细节（架构、性能数据、踩坑）；
   - 与你自己的经验/项目能呼应的点（最有价值，最像真人）。

3. **生成评论草稿**（直接输出，不需再调工具）：
   - **开头**：指出文章中具体的一句话 / 一个数据 / 一个设计，证明你真读了；
   - **中间**：给出你的真实看法或补充——最好结合你做过的事（自己的项目、踩过的坑）；
   - **结尾（可选，自然带链接）**：只有当你的经历确实相关时，才顺带提一句自己的文章
     （如「我最近也写过一篇类似的……」，附 `https://erishen.cn/<slug>/` 链接）。
     链接是**补充不是目的**：写不出来就删掉结尾，不要硬塞。

4. **只出草稿，说明提交方式**：把草稿放在代码块里方便复制；明确提醒「请人工粘贴提交」，
   本技能不做任何自动发布。可以给出 1 条主草稿 + 1 条更短的备选（备选可去掉链接）。

## 注意事项

- **真诚优先**：评论要具体（引用原文细节），不要「好文」「学习了」「收藏了」这类空话。
- **链接克制**：一句话带过即可，不解释、不推销；社区对「评论里硬塞链接」识别很严，
  一条评论最多一个站内链接，且必须与讨论内容强相关。
- **身份**：以用户本人身份（默认）起草，不要虚构他人身份；称呼作者用 ta 文章里的署名即可。
- **只读不改**：本技能不修改对方文章、不自动提交评论、不关注/点赞作者。
- **平台差异**：掘金 / 思否对链接较宽容；知乎外链环境差，建议草稿默认不带链接。
